# StatusBadge.tsx に関する疑問と回答メモ

### Q1. `import { ... } from "../types/inquiry"` で呼び出しているインポート元には何の要素があるの？
**A.** ここでは、アプリ全体で使い回す**「ステータスに関する共通のルール（型や文字データ）」**を持ってきています。具体的には以下の3つです！
1. `InquiryStatus`: ステータスは `"pending"`、`"in_progress"`、`"completed"` の3種類だけだよ、という型のルール。
2. `inquiryStatusLabel`: `"pending"` のときは日本語で「未対応」、英語で「Pending」にするよ、という日・英の翻訳文字データ。
3. `Language`: 言語は `"ja"` か `"en"` のどちらかだよ、という型のルール。

---

### Q2. `type StatusBadgeProps = { status: ... }` ここら辺はステータスを管理しているの？
**A.** 管理というよりも、**「このバッジを表示するために必要な『材料』を指定している場所（取扱説明書）」**です！
このバッジパーツ（子）を画面に出すために、親（TableやDetailPage）から**「今のログのステータス（status）」**と**「今の言語（lang）」**の2つを必ず仕送り箱に入れて送ってね！とTypeScriptに指示をしています。

---

### Q3. `const classMap: Record<InquiryStatus, string> = { ... }` はステータスの言語やそれぞれの意味を表しているの？
**A.** いいえ、ここは言葉の意味ではなく、**「ステータスごとに『どのCSSクラス（色や光らせ方）』を適用するかをカチッと決めるためのマッピング表」**です！

* `"pending"`（未対応） ➔ `.badge-pending`（インデックスCSSで定義した、消去レーザーのようなネオンピンク色）
* `"in_progress"`（対応中） ➔ `.badge-progress`（サイバーなネオンブルー・シアン色）
* `"completed"`（完了） ➔ `.badge-completed`（世界が美しさを取り戻したときのネオングリーン色）

このように、ステータスの文字列（鍵）と、CSSのクラス名（値）を1対1でペアにしています。

---

### Q4. `return <span className={...}>【{...}】</span>;` ここは何をしているの？
**A.** **Q3で選んだ「ネオンカラーのCSSクラス」と、Q1で持ってきた「日・英翻訳テキスト」をガッチャンコして、最終的なバッジの文字を画面に出力しています！**

* `className={classMap[status]}`
  * 例：もしステータスが `pending` なら、自動的に `className="badge-pending"` になり、ピンク色に光ります。
* `{inquiryStatusLabel[lang][status]}`
  * 例：もし言語が `ja` でステータスが `pending` なら、自動的に「未対応」という文字に化けます。
  * もし言語が `en` でステータスが `pending` なら、自動的に「Pending」という文字に化けます。

結果として、画面には **【未対応】**（ピンク光り）や **【Completed】**（グリーン光り）という美しいキャプテンEO仕様のバッジが出現する仕組みになっています！
