# App.tsx（司令塔・最親コンポーネント）に関する疑問と回答メモ

### Q1. `const INITIAL_INQUIRIES: Inquiry[] = [ ... ]` は何をしている？
**A.** **アプリを起動したときに、最初に画面に表示される「初期データ（3件の宇宙ログ）」を定義している。**
* `: Inquiry[]` ➔ 「`Inquiry` 型の設計図に100%合致したデータの『配列（リスト）』ですよ」というTypeScriptの型指定。
* **キャプテンEOの小ネタ：** データの文面には、フーター、メジャードモ、ファズボール、最高指導者といった、映画に登場するキャラクターのトラブルが精密に散りばめられている。

---

### Q2. `function App() { ... }` の中にある4つの `useState` の役割は？
**A.** **アプリ全体が正しく動くための「4つの超重要データ（状態）」を、司令塔として一元管理（記憶）している。**
1. `inquiries`: 宇宙ログのデータ配列そのものを記憶。初期値は Q1 の 3件のデータ。
2. `currentPage`: 現在どの画面（一覧、詳細、概要、登録）を開いているかの文字列を記憶。初期値は `"list"`（一覧）。
3. `selectedId`: 詳細画面で「何番のログ」を開いているかのID番号を記憶。何も選ばれていないときは `null`。
4. `language`: 現在の言語設定（`"ja"` または `"en"`）を記憶。初期値は `"ja"`（日本語）。

---

### Q3. `handleUpdateStatus` や `handleDeleteInquiry` などの関数群は何？
**A.** **子コンポーネント（各画面）からの要請を受けて、Q2で管理しているデータを書き換えるための「命令コマンド群」である。**
* `handleUpdateStatus` ➔ 詳細画面でプルダウンが変えられたとき、`.map` を使って対象のログだけステータスを書き換える。
* `handleDeleteInquiry` ➔ 削除ボタンが押されたとき、`.filter` を使って対象のログを配列から消去し、自動で一覧画面（`"list"`）へ戻す。
* `handleAdd` ➔ 登録画面でフォームが送信されたとき、`Date.now()` で新しいIDを発行し、スプレッド構文（`[...inquiries, newInquiry]`）を使ってログを最後尾に追加する。

---

### Q4. `const t = { ja: { ... }, en: { ... } }[language];` はどういう仕組み？
**A.** **現在の言語設定（`language`）に応じて、ナビゲーションバーやタイトルの「文字の塊」を丸ごと一瞬で切り替える仕組みである。**
* `[language]` の部分がミソで、もし状態が `"ja"` なら左側の `ja` オブジェクトが選ばれ、`"en"` なら右側の `en` オブジェクトが変数 `t` に代入される。
* これにより、JSX（画面の見た目）側では `{t.navList}` と書くだけで、「一覧」か「LIST」かが自動的に出し分けられる。

---

### Q5. `<nav className="eo-nav">` の中にあるボタンの動きは？
**A.** **画面上部のナビゲーションメニューであり、クリックした瞬間に状態（`setCurrentPage`）を書き換えて画面をジャンプ（遷移）させている。**
* 例：`setCurrentPage("about")` が実行されると、Reactがそれを検知して画面全体の描画を自動でリフレッシュする。
* **言語切り替えボタン：** 「もし今の状態が `ja` なら `en` に、そうじゃなければ `ja` にする」というトグル処理。文字は宇宙共通プロトコルのため、日・英どちらも `We are here to change the world!` で完全に固定されている。

---

### Q6. `<main>` タグの中の `{currentPage === "list" && ( ... )}` は何をしている？
**A.** **Reactにおける「条件付きレンダリング（画面の出し分け）」の核心部分である。**
React Routerなどの外部ライブラリを使わず、`currentPage` の文字列（`"list"`, `"detail"`, `"create"`, `"about"`）をチェックし、合致する「1つの画面コンポーネント」だけを狙い撃ちで画面に登場させている。

* **データのバケツリレー（Propsの伝播）：**
  ここで各画面コンポーネントを呼び出す際、Q2・Q3で用意した最新のデータ（`inquiries`, `language`）や、データを操作するための関数（`onSelectInquiry` や `onDeleteInquiry`）を、Props（仕送り箱）に詰めて下の画面へ引き渡している。
